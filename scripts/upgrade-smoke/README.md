# Upgrade smoke test

Boots the built server (`dist-server`) on populated databases from older releases and checks that the migration chain applies, data survives and logins work. It is the safety net for the TypeScript migration, because the migration loader (`MigrationManager`) executes the emitted `.js` files as text.

```
npm run smoke:upgrade                      # builds, then runs everything
node scripts/upgrade-smoke/run.js --only v2.14 --keep   # one fixture, keep the temp dir for inspection
```

It needs `ffmpeg`/`ffprobe` on `PATH` (or `FFMPEG_PATH`/`FFPROBE_PATH`); they are not exercised, but the server refuses to start without them and the sandbox/CI cannot download them. `ABS_SMOKE_PORT` (default 13500) sets the first port used.

## Checks
1. Emitted `dist-server/server/migrations/*.js` match `server/migrations` and each exports `up()`/`down()`.
2. Per fixture: server boots, every migration newer than the fixture's version ran (derived from the migrations directory, so new migrations are expected automatically), MigrationManager reports success, no ERROR lines, `root` and `reader` log in, the API lists 2 libraries, every pre-existing table keeps its row count, and `migrationsMeta.version` equals `package.json`'s version.
3. Row-count differences that exist today are pinned in `EXPECTED_ROWS_AFTER` in `run.js` (with the reason). A new difference fails the run.

## Fixtures
`fixtures/` holds real databases generated by old servers (see `fixtures/README.md`). They contain test accounts only (`root`/`rootpass123`, `reader`/`readerpass1`) and their own `tokenSecret`. Paths are `/PLACEHOLDER/...`; `run.js` rewrites `backupPath` to a temp dir at runtime. Add a fixture when a new release changes the schema. Regenerate with `gen-fixture.js` (usage in `fixtures/README.md`; it lives here, not under `test/`, because mocha loads every `.js` under `dist-server/test`).
