- Findings (recorded as-is; see the snapshot for exact values):
  - `.ignore` in the library root is ignored as a plain dotfile; only a `.ignore` in a subdirectory hides that directory (and everything below it). `Ignored2/Sub/.ignore` hides `Sub` but not `Ignored2/keep.mp3`.
  - `@eaDir` matches anywhere in the path as a substring: `Book/my@eaDirbook.mp3` is ignored.
  - Ignore extensions are matched case-insensitively (`01.TMP` ignored); `.partial` is not ignored.
  - `Deep/a/b/c/d/e.mp3` becomes one item `Deep/a/b/c/d` with title `d`, series `c`, author `B` (only the last three folder levels are used, the rest of the path is dropped from the metadata).
  - `Series Title 2 of 3/Book` gives author `Series Title of 3` (the name parser drops the lone `2`).
  - `Title[B0015T963C]` (no space before the bracket) is not an ASIN and stays in the title; lowercase ASIN is not matched either.
  - Sequence is only parsed when there is a series folder (`Author/Book 2 - Title` keeps `Book 2 - Title`). `101 Dalmations` is not a sequence, `101. Dalmations` would be.
  - A CD dir is recognized only directly below the item folder: `Book/Extras/CD 2/b.mp3` is filed as `Extras/CD 2/b.mp3` of `Book`; `CD 1/c.mp3` at the root groups under `CD 1`; `CD 1000` (4 digits) is not a CD dir.
  - In a podcast library every subfolder with audio is its own item: `Podcast B/Season 1` and `Season 2` are two podcasts titled `Season 1`/`Season 2`, while the group function (pure, unit test) folds only when files sit directly in the top folder. Root files and ebooks are ignored.
  - `ebook` files (`.epub`, `.cbz`) in a folder with audio get `isSupplementary: null` on first scan; only files added to an existing item are set to `true`.
  - `hasLibraryFileChanges` returns a count (number), not a boolean as its JSDoc says.
  - A rename inside an item (same inode) is reported as a modification, with `hasAudioFileChanges` true and no add/remove.
- Singleton/harness problems: pure-function tests (no `startApi`) write the real `Logger` debug/error output to the console; harmless but noisy. Snapshots mask nothing for log lines: timestamp-change and inode log lines are filtered or masked in the test because they depend on whether two writes land in the same millisecond.
- Platform notes: `fs.realpathSync` on the temp dir is needed on macOS (`/var` -> `/private/var`). No case-variant file names are created (case-insensitive FS). Unicode names are written NFC; APFS preserved them.
- **Pre-existing failure on this machine, not from this step:** `AuthRoutes.test.js` (4 tests) fails when the system time zone is not UTC (snapshot has `"timeZone": "UTC"`; here `Pacific/Auckland`). Run the suite with `TZ=UTC`. Suggest the cloud session pins `process.env.TZ` or masks `timeZone` in that snapshot.

- Findings (recorded as-is, snapshots show the exact values):
  - **The copy of metadata.json saved under `<metadata>/items/<id>/` is read back as the last metadata source (`absMetadata`) on every rescan and wins over everything before it.** Changing tags in an audio file updates the file's `metaTags` but not the book's title/author/narrator; adding or removing an audio file does not rebuild chapters (they stay as saved). Deleting the folder's metadata.json also leaves the values in place. Input: scan, rewrite `01.mp3` with other `album`/`artist`, rescan (test "tags changed in an audio file", "audio file added/removed", "metadata.json ... deleted").
  - Replacing the only audio file with a corrupt file keeps the old audio entry on the book (the corrupt file's scan returns null and the old entry is not dropped); the item is not set missing and keeps its old duration.
  - `getTrackAndDiscNumberFromFilename` calls `partbasename.replace(publishedYear)` without a replacement, which inserts the text `undefined` instead of removing the year (the track number still comes out right because `undefined` has no digits).
  - Series from tags: `series` + `series-part` with `;` lists of unequal length are not split (`name: "S1; S2"`, `sequence: "1; 2; 3"`); the `grouping` tag is only used when `series` is empty.
  - Chapters: embedded chapters in the first file are used for the whole book when file 2 has identical chapters, otherwise per-file chapters are concatenated and chapters shorter than 0.1s are dropped with a warning; tag titles are used as chapter titles only when every file has a unique title different from the book title.
  - metadata.json: logs `Found metadata file` even when the JSON is invalid (the file is then ignored); a bad chapter drops all chapters but the other fields still apply; `subtitle: 5` becomes `"5"`; `narrators` arrays are de-duplicated and non-strings dropped; `genres: []`/`authors: []` do not clear existing values, `explicit: "true"` becomes `true`.
  - nfo: `Title: A: B` splits into title `A` and subtitle `B`; `Unabridged: Yes` sets `abridged` false. Precedence default order is folder, tags, nfo, txt, opf, metadata.json, so an opf title beats nfo and tags, while `desc.txt` beats the nfo description.
  - Ebook-only folders take their metadata from the epub, or from ComicInfo.xml for cbz (`Series` + `Number` -> title `Comic Series 5`); a cbz without ComicInfo keeps the folder name as title. When audio exists, epub metadata is ignored entirely. The epub is preferred as the ebook file; the others become `isSupplementary: true`. A pdf/mobi alone becomes the ebook file (no parser, folder name as title).
  - With `audiobooksOnly`, the ebook file is cleared on rescan and the file flips to supplementary; ebook-only folders are not grouped at all.
  - A multi-disc book (`CD 1/01.mp3`, `CD 1/02.mp3`, `CD 2/01.mp3`) gets chapters titled by file base names (`01`, `02`, `01`).
  - The extracted embedded cover goes to `<metadata>/items/<id>/cover.jpg` (`cover.png` for epub/cbz art), or into the item folder with `storeCoverWithItem`, except for `isFile` items.
- Singleton/harness problems: `global.ServerSettings` is replaced in some tests (`storeCoverWithItem`, `storeMetadataWithItem`); the harness `stop()` restores the old value. `Database.getAuthorIdByName` needs `libraryFilters.getFilterData` first; `scanLibrary` does that. Item creation order and `libraryFiles` order follow the filesystem, so `stable()` relabels uuids by item/author/series name and sorts log/event lists for multi-item scans, and `scrub()` sorts `libraryFiles`. Log lines about changed mtime/ctime/birthtime are dropped (they depend on whether two writes share a millisecond).
- Platform notes: values depend on the ffmpeg build. Recorded with Homebrew ffmpeg 9.0.1: durations are rounded to whole seconds, chapter boundaries are whole seconds, ogg fixtures use libopus (the Homebrew build has no libvorbis), bit rates, sizes, timeBase and the encoder tag are dropped. If a Linux ffmpeg yields a different `format` string, `language` or cover codec, those snapshot lines are the first suspects. `fs.realpathSync` is used for temp dirs. Fixture files are set to a future mtime when "modified" so the change is detected regardless of mtime resolution.
